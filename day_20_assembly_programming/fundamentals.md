# MIPS fundamentals

## Assembly language

Assembly language provides a textual representation of processor instructions and related assembler directives.

A MIPS source file normally contains:

- directives
- labels
- instructions
- comments

A typical structure is:

`.data`

followed by static data, then:

`.text`

followed by executable instructions.

## Registers

MIPS provides a fixed set of general-purpose registers.

A register holds a value directly available to instructions.

The examples use registers according to conventional roles rather than treating every register as interchangeable.

`$t0-$t9` are used for temporary calculations.

`$s0-$s7` are used for values that procedures must preserve.

`$a0-$a3` carry procedure arguments.

`$v0` carries a return value.

`$ra` stores the return address generated by `jal`.

`$sp` points to the active stack area.

`$fp` can provide a stable reference to a procedure's stack frame.

## Immediate values

An immediate value is encoded as part of an instruction.

For example:

`addi $t0, $t0, 1`

adds one to `$t0`.

`li` is a pseudo-instruction used to load a constant.

## Arithmetic

Addition:

`add $t0, $t1, $t2`

Subtraction:

`sub $t0, $t1, $t2`

Immediate addition:

`addi $t0, $t0, 5`

Multiplication:

`mul $t0, $t1, $t2`

Division:

`div $t1, $t2`

After division, `mflo` retrieves the quotient and `mfhi` retrieves the remainder.

## Memory

MIPS uses explicit load and store instructions.

For a word:

`lw $t0, 0($t1)`

loads a 32-bit value from memory.

`sw $t0, 0($t1)`

stores a 32-bit value into memory.

The processor does not automatically load variables into registers.

The programmer decides when memory is accessed.

## Addresses

An address identifies a memory location.

`la $t0, array`

loads the address of the label `array`.

The contents at that address are not loaded by `la`.

To load the actual word:

`lw $t1, 0($t0)`

This distinction between addresses and values is fundamental.

## Branching

A conditional branch evaluates a condition and changes control flow if the condition is true.

`beq $t0, $t1, equal`

branches when the two registers contain equal values.

`bne $t0, $t1, different`

branches when the values differ.

`slt $t0, $t1, $t2`

sets `$t0` to 1 when `$t1` is less than `$t2`.

A common pattern is:

`slt $t0, $t1, $t2`

`bne $t0, $zero, less_than`

This translates a less-than condition into a branch.

## Labels

A label identifies a location in the program.

Example:

`loop:`

The instruction after the label executes when control reaches that location.

Labels make branches and jumps readable.

## Jumps

`j label`

performs an unconditional jump.

`jal procedure`

jumps to a procedure and stores the return address in `$ra`.

`jr $ra`

jumps to the address stored in `$ra`.

## Procedure arguments

A caller can place arguments into:

`$a0`

`$a1`

`$a2`

`$a3`

For example, a two-argument addition procedure can receive its operands in `$a0` and `$a1`.

## Return values

A procedure commonly places its result in `$v0`.

The caller can then move the value into another register or use it directly.

## The stack

The stack is memory used for temporary procedure state.

It is especially important when:

- a procedure calls another procedure
- a procedure has local data
- recursion is used
- saved registers are required

A stack allocation changes `$sp`.

The same number of bytes must be released before returning.

## Word size

The examples operate on 32-bit integer words.

Each word occupies four bytes.

For array element `i`:

`offset = i * 4`

The `sll` instruction can multiply an integer by four:

`sll $t1, $t0, 2`

because shifting left by two bits multiplies an unsigned integer by four.

## Syscalls

The simulator provides services through the `syscall` instruction.

For example, to print an integer:

`li $v0, 1`

`move $a0, $t0`

`syscall`

The number in `$v0` selects the simulator service.

## Important distinction

MARS and RARS are simulators.

Their syscall services are educational interfaces provided by the simulator environment.

They should not be confused with instructions implemented directly by the processor.

The MIPS processor understands instructions such as `add`, `lw`, `sw`, `beq`, `j`, and `jal`.

The simulator interprets `syscall` and provides the requested console service.
